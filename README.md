# 业务改版前后对照分析系统

对业务改版（上线）做前后对照分析：**不只返回一个差值，而是给出影响范围**——点估计、Bootstrap 置信区间、对照组 DiD、去年同期净效应、参数敏感性区间，并附带完整证据链与可追溯的参数/数据版本。

## 能力总览

| 能力 | 实现 |
|---|---|
| 分层分析 | 按城市层（T1/T2/T3）分层估计，pre 期固定权重聚合总体，同时报告朴素总体与**构成影响（pp)** |
| 匹配窗口 | 每个 post 日匹配前 N 个同星期 pre 日（默认 4 周），校验匹配对**绝不跨越上线日**（无后视泄漏） |
| 同期对照 | 去年同期窗口（364 天偏移、星期对齐）剔除季节性；同期对照组 DiD 剔除共时冲击 |
| 缺失期处理 | `drop` / `interpolate`（同星期邻居均值插补）两种策略，缺失单元全部记录 |
| 样本构成变化 | users 份额 pre/post 对比，超阈值告警；构成调整值 vs 朴素值之差即构成影响 |
| 指标口径变化 | 口径注册表 + 双报重叠期换算因子估计（Σnew/Σold），`adjust` / `flag_only` 两种策略 |
| 异常事件 | 事件注册表，估计事件超常量（按层加权），`exclude` / `include` 两种处理策略 |
| 影响范围 | 点估计 + 95% CI + DiD + 剔季节性净效应 + 80 组参数变体的敏感性区间 + 稳健性结论 |
| 可追溯 | 每次运行持久化参数快照（param_hash）、数据版本内容哈希、代码版本、结果哈希；同参同版本重跑结果哈希一致 |
| 验证 | 时间边界 8 项检查（重叠/连续/泄漏/星期对齐/覆盖度）；回补数据 4 项检查（时间戳/离群 z 分数/分布/策略一致性） |

## 快速开始

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m uvicorn app.main:app --port 8000
# 打开 http://localhost:8000
```

首次启动自动载入演示数据（两个数据版本）。运行测试：

```bash
.venv/bin/python -m pytest tests/ -q
```

## 演示数据内置场景

- **2026-09-01 改版**：处理组分层真实提升 T1 +8% / T2 +6% / T3 +3%，对照组无效应
- **构成变化**：改版后处理组 T3 用户 +30%（低客单层占比上升）
- **口径变化**：gmv 2026-09-15 起 v1→v2（含运费 ×1.10），09-08~14 双报重叠期
- **异常事件**：99大促（09-10~12，处理组 ×1.25）、支付网关故障（08-20，全量 ×0.5）
- **缺失期**：08-15 T2/处理组、09-25 T1/对照组
- **回补数据**（仅 v2026.11.01）：08-14 正常回补；09-20 异常回补（gmv ×3，被离群检查捕获）
- **去年同期**：2025-09 处理组 +2% 季节性，供同期对照剔除

## API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/datasets` | 数据版本注册表（行数、内容哈希） |
| GET | `/api/events` | 异常事件注册表 |
| GET | `/api/metrics/registry` | 指标口径注册表 |
| POST | `/api/runs` | 创建分析运行（参数快照见 `app/schemas.py`），返回完整结果 |
| GET | `/api/runs` | 运行历史（param_hash / result_hash / 数据版本 / 代码版本） |
| GET | `/api/runs/{id}` | 重放历史运行结果 |
| POST | `/api/seed?force=true` | 重建演示数据 |

## 方法说明

**效应估计**：post 日 d 的相对效应 = v(d) / mean（匹配 pre 日） − 1；总体按 pre 期处理组份额做固定权重聚合（构成调整）。CI 按天 Bootstrap（默认 1000 次）。

**影响范围**：敏感性扫描对 匹配窗口 × 缺失策略 × 事件策略 × 回补策略 × 口径策略 做网格（≥64 组变体），输出效应估计的 [min, max]；结论分档：正向且稳健 / 正向但敏感 / 负向…/不显著。

**证据链**：load_dataset → caliber_adjustment → prepare_series → validate_boundaries → validate_backfill → estimate_effects → composition_check → event_impacts → sensitivity，每步记录输入摘要的 SHA-256 短哈希。

## 目录结构

```
app/
  main.py       # FastAPI 入口与路由
  pipeline.py   # 分析流水线（窗口/匹配/效应/敏感性/证据链）
  validate.py   # 时间边界与回补数据验证
  stats.py      # 纯标准库统计（Bootstrap、稳健 z）
  schemas.py    # 参数快照与哈希
  storage.py    # SQLite 持久化（版本/明细/事件/口径/运行）
  seed.py       # 演示数据生成（两个数据版本）
static/         # 单页前端（样本流/趋势/分层/对照/敏感性/证据链）
tests/          # 23 个测试：边界、回补、缺失、事件、端到端、可复现性
```
